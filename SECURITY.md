# Security Policy

## Report vulnerabilities privately

For suspected security issues in this repository, use GitHub's **Security**
tab and the private **Report a vulnerability** option if available.

If private reporting is not available, [open a security contact request](https://github.com/mohammadrezwankhan/awesome-battery-data/issues/new)
without including exploit details, tokens, credentials, private URLs,
personally identifying information, or sensitive logs. Ask the maintainer to
provide a private reporting channel before sharing technical evidence.

Do not post suspected vulnerabilities in public issues or pull requests.

## Scope and versions

This is an educational resource directory and offline teaching lab.
No version-support matrix, response-time guarantee, or security service
level agreement is published. Include the repository commit or release,
affected file or dependency, reproducible conditions, and practical impact in
a **private** report.

Links to external datasets and projects are references, not endorsements or
security guarantees. Review each external project's licensing, provenance,
and security guidance before downloading or executing anything.

## Coordinated disclosure

Maintainers may review, reproduce, and coordinate remediation or disclosure.
Do not make security claims on behalf of third-party data providers or
publish sensitive details before a suitable private disclosure channel exists.
